# References

## Academic References

### A1. What We Don't Know About Spreadsheet Errors Today: The Facts, Why We Don't Believe Them, and What We Need to Do
- **Author:** R. R. Panko
- **Year:** 2015
- **Published in:** Proceedings of the EuSpRIG 2015 Conference, European Spreadsheet Risks Interest Group
- **Link:** https://arxiv.org/abs/1602.02601
- **What I learned:** This paper first explains how the human mind works, and then it explains how and why we make mistakes in Excel. It shows that mistakes in Excel are very hard to notice, and their results can be very serious. From this paper, I saw the chance of human mistakes in a concrete way. I also saw how useful my solution can be. I use this paper as a supporting study that shows why planning with Excel is a problem.

### A2. Personnel scheduling: A literature review
- **Authors:** J. Van den Bergh, J. Beliën, P. De Bruecker, E. Demeulemeester, L. De Boeck
- **Year:** 2013
- **Published in:** European Journal of Operational Research, 226(3), 367-385
- **DOI:** https://doi.org/10.1016/j.ejor.2012.11.029
- **What I learned:** This paper is a review that studies and classifies research about personnel scheduling. In the paper, constraints are divided into groups. Two of these groups, cost measures and time-related constraints, are exactly the topics that my website will handle. The budget limit in my system belongs to the cost measures group. Working days, leave days and the weekly day limit belong to the time-related constraints group. So my project is a system that manages known constraint types in a concrete way and reduces planning mistakes. I use this paper as a supporting study that shows my constraints are known constraint types in academic research.

## Technical References

### T1. FastAPI Documentation
- **Organization:** FastAPI
- **Year:** 2026 (accessed)
- **Link:** https://fastapi.tiangolo.com/
- **What I learned:** FastAPI is a modern backend web framework. Its advantages are that it is fast and it makes the code shorter. For example, if I use Flask, the code becomes longer, because I need to write more if-else statements to check the incoming data. In FastAPI, if I write type hints, the data is rejected automatically when it does not match the type I defined. I can also test the backend directly from the automatically created test page (Swagger UI).

### T2. React Documentation - Learn React
- **Organization:** Meta Open Source
- **Year:** 2026 (accessed)
- **Link:** https://react.dev/learn
- **What I learned:** React is a JavaScript library that updates the screen automatically and correctly when the data changes. If I used plain JavaScript, I would need to update every related part of the screen by hand each time the data changes. This would make the frontend code more complex and easier to break. In React, I write components that create the screen from the data, and when the data changes, React updates the screen by itself. It is a little harder to learn at the beginning, but it gives a more organized and correct user interface.
